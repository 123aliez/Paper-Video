# 阶段 2：写视频脚本——讲清论文，让观众听懂结论是怎样得来的

本指南把 [ljg-paper](https://github.com/lijigang/ljg-skills/tree/master/skills/ljg-paper)（MIT）讲论文的思路改写成视频口播的写法。文章读者可以回读，视频观众只听一遍，每秒大约四个字，所以下文多了一些“为耳朵写作”的要求。格式规范见 `script-format.md`，完整范例见 `examples/qmf/script.md`。

## 观众是谁

默认观众是 B 站学术区里**愿意动脑、但不熟悉这个子领域**的人：有高中到本科的数学常识（知道平均数、概率、函数），不认识该领域的术语、数据集和惯用做法。用户指定了观众时以用户为准。

由此推出两条规则：

- 每个领域术语**第一次出现时就地解释**，用“叫……”“即……”接一句白话。例如：“把图和文的判断按固定权重相加，叫晚期融合”“深度图，即每个像素离镜头多远”。观众在记住名字之前，应该已经明白它指什么。
- 例子不能暗中要求行业知识。用“缓存”“接口”解释 AI，外行照样听不懂；用“投票人砝码不变”解释固定权重，人人都能听懂。

## 三个目标（分别检查，不能相互替代）

1. **说清论文做了什么。** 看完前两章，观众就能说出研究问题、作者的主要贡献，以及方法怎么起作用。论文中不可省略的主线都要交代。
2. **让观众明白为什么要修正原来的看法。** 从具体问题出发，先说通常怎么想（如“多一路信息，总不会更差吧？”），再用论文证据展示哪里不够（MVSA 噪声到 5 时，晚期融合反比单用文本低 6 个点），最后说明作者补充了什么。变化可以是纠正、补充或缩小适用范围，不必制造戏剧性反转。
3. **让观众能自己解释结果。** 如果论文有统一机制（如“权重与损失负相关 → 协方差项为负 → 上界更低”），观众应能用它解释至少两个不同发现，并推想改变条件后会怎样。区分论文验证过的结论和依据机制的推想。

## 按贡献类型安排重点

| 主要贡献 | 视频要讲清 |
|---|---|
| 方法或干预 | 改了哪个动作；输入经过哪些步骤；结果为什么可能不同；用一组自拟小数字把一次计算走完 |
| 解释或理论 | 哪些量怎样相互作用；推导每一步靠什么前提；能解释哪些现象；什么条件下不成立 |
| 测量或评测 | 旧指标漏掉什么；新评测测到什么；“测到差异”与“解释了差异”之间还差什么 |
| 资源或系统 | 提供了什么数据或能力；降低了哪种成本或限制；仍受什么约束 |

章节数量和顺序由论文决定。QMF 范例是“理论 + 方法”的混合论文，五章依次为：开场与痛点 → 定理推导 → 示意图读法 → 方法与正则化 → 实验解读与局限。纯方法论文可以把理论章换成“方法一步步怎么跑”；评测论文可以把方法章换成“新评测测什么”。

## 叙事骨架

一条从问题出发、最后回到问题的线：

1. **开场（约 15%）**：具体场景（谁、拿着什么数据、要判断什么）→ 自然的预期 → 论文里推翻或补充这个预期的证据（带上下文的数字）→ 原因的直观说法 → 对这条证据本身的保留意见。
2. **核心机制 / 理论（约 25%）**：为什么作者的思路能起作用。推导按步骤讲，每一步说清靠什么前提，前提论文没写的直接指出。
3. **方法（约 25%）**：方法实际运行一次的过程。用自拟小数字走一遍完整计算，在口播和画面上都标明“仅作演示”，数字用代码复算。
4. **实验（约 20%）**：先教观众怎么读图表（箱线图、消融各是什么意思），再讲中心实验：问什么、固定什么、比谁、结果、意义、不能推出什么。领先幅度小于标准差、前后表格不一致等情况要直说。
5. **局限与收尾（约 15%）**：分“论文自述”和“我们补充”两层；最后用两三句话回到开头的问题，只总结前文，不加新证据、新术语。

相邻章节可以递进，也可以并列。递进时说清后一章依赖前一章的哪个结论；并列时说清各自补充什么。

## 口播：为耳朵写作

- **口播里不出现符号**。公式念成中文（“负的温度，乘以各类 logits 除以温度、取指数、求和、再取对数”），公式本身放进画面的 LaTeX 块。希腊字母、上下标、等号、不等号都不进口播。
- **短句，主谓宾清楚**。每个分句（逗号之间）不超过约 25 个字，因为字幕按标点切分，太长的分句会超出两行。
- **一个镜头讲一件事**。每镜 40–150 字（10–38 秒）；超过 150 字就拆镜。
- **同一概念始终用同一说法**，不为避免重复而换词。
- **英文专名保留论文写法**（Table 1、BERT、MVSA），TTS 读错的写进 `video.json` 的 `tts_replace`，字幕不受影响。
- **引用位置要具体**：“看 Table 1 的图文情感数据集 MVSA”“Figure 2 右图”，方便观众回去对照原文。
- **口播只说内容，不交代制作过程**（不说“我们查了资料”“下面这个动画”）。

## 数字：先给上下文，再给数，再说意义

- 数字出现前交代实验在问什么、条件是什么、和谁比；数字之后说明差异的实际意义和限制。
- 精确到论文给的位数，不四舍五入改写；口算出来的差值（如“低 6 个点”）在附录写明算式。
- 不堆数字：一个镜头里关键数字一般不超过四到六个，其余放进画面或附录。
- 领先幅度要和标准差比：“只比 TMC 高 0.58，标准差是 1.84”。
- 表与表不一致时选定一个口径（如“一律以 Table 1 为准”），写进制作说明。

## 诚实标记（这是这类视频的价值所在）

视频不替作者补全没说的东西。下面几种情况要在口播里直接说出来，画面上用红色标签标注：

| 情况 | 口播示例 |
|---|---|
| 论文没定义 / 没说明 | “文本加‘空白噪声’，论文没定义，也没说强度在文本上指什么。” |
| 推导缺前提 | “这要求权重都不小于零、加起来等于 1，论文推导没写出这个前提。” |
| 自拟演示值 | “设系数负 0.1、常数 0……这两个系数论文没报告，仅作演示。” |
| 推测 | “可能算的是不确定度与损失的相关……论文没写清，这是推测。” |
| 结论边界 | “比的是上界不是实际误差，天花板更低，不等于实际一定更低。” |
| 相关不是因果 | “这只是 4 个点的趋势，不是因果证明。” |
| 示意图不是定理 | “这是示意图，不是严格结论。” |

## 画面：可以直接做成动画

画面描述就是给 Manim 制作阶段的施工图，要具体到能直接写代码：

- **出现什么、以什么顺序、和口播的哪个词同步**：“讲到 Rademacher 时插入小动画……”
- **优先用原文图表**：截取 PDF 里的表格和图，高亮具体单元格、柱子、曲线；需要讲机制时再自己画。
- **每个画面标出处角标**：“出处：Table 1，MVSA，平均准确率（%）”。
- **公式全部写成 LaTeX 块**（xelatex + xeCJK 编译，`\text{}` 里可以写中文）。
- **注明连续镜头**：“同一张曲线图”“镜头推向叉号 f*”，制作时用 carry_out / carry_in 衔接。
- **示意与实测分开**：自己画的曲线注明“示意，不是论文数据”。
- **不要求照片级素材**：场景插画用几何图形或程序生成（见 `examples/qmf/make_assets.py`）。

## 例子与演示数字

- 自拟例子要对应论文里的角色和关系，并让观众知道这是帮助理解的例子，不是作者做过的实验。
- 演示数字要选能**避开论文没讨论的边界情况**的值（QMF 4-6 选权重差 0.3 小于 κ 差 0.8），并在存疑点里记录原因。
- 所有演示计算用 Python 复算，结果写进附录①，标“自拟，代码复算”。

## 写完后的检查

### 1. 格式与时长

```bash
python <skill>/scripts/script_tool.py check script.md --target-min 10 --write
```

检查镜号、空口播、口播中的符号、过长分句、每镜字数、附录是否齐全、口播里的数字是否都在附录①里，并按 4 字/秒重算时间码。预计成片超过目标时长时会给出要删的字数。

### 2. 数字复核

把附录①逐条和 `production/assets/text/p*.txt`（或 `pdftotext` 输出）对照，确认数字、所属行列和条件都对。演示计算重新跑一遍代码。

### 3. 独立观看检查（借鉴 ljg-paper 的独立阅读检查）

启动一个**新上下文的子代理**（Agent 工具，general-purpose），只给它全部口播文本（按镜头顺序拼接，等同于观众听到的内容），不给论文、research.md 或你的预期答案。让它按顺序回答：

1. **需要回听的地方**：从哪句开始需要倒回去听，或自己补背景、补画面？引用原句并说明缺什么。
2. **全文复述**（不引用分数）：问题、作者做法、结果、限制；各章分别起什么作用。→ `NARRATIVE_PASS / FAIL`
3. **研究问题与贡献五问**：已有做法解决不了什么；作者提出了什么；方法如何起作用；中心实验怎样支持结论；证据最多支持到什么程度。答案空泛到能套到别的论文上就算失败。→ `PAPER_IDENTITY_PASS / FAIL`
4. **三句认识变化**：原先怎么想；论文补充或修正了什么；现在怎么判断、有什么限制。→ `UNDERSTANDING_PASS / FAIL`
5. **结果解释**：用文中机制解释两个不同发现，再改变一个条件做预测，注明哪些是推想。→ `RECONSTRUCTION_PASS / FAIL`

任何一项失败，或第 1 项指出的句子影响主线理解，就改脚本，改完重新检查（新开一个子代理，不复用旧结论）。实际回答和判定记进 research.md。子代理的理解只是有限证据，不等于真实观众一定能懂；用户说没看懂时，以用户为准。

## 容易出错的地方

- **例子讲清了，论文没讲清**：观众记住了“投票人和砝码”，却说不出 QMF 的贡献是什么。回到原文重新组织，而不是只修句子。
- **用一个例子硬撑全片**：换例子时交代它补充了哪一层。
- **贡献说得太空**：“提出了一种新方法”不算；要说“用能量分数估计每一路有多拿不准，再用历史平均损失做排序正则”。
- **只报最好的数字**：隐去例外（干净数据上不总是第一）会误导观众。
- **口播里塞公式**：“w 等于 alpha u 加 beta”听不懂；说“权重是能量的直线函数：负系数乘能量加常数”，公式放画面。
- **结尾加新东西**：收尾只总结前文。
